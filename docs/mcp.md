# MCP servers

MCP, the Model Context Protocol, is a standard way for a program to offer tools to an AI application. We use it so that agents reach our data through a small, explicit, inspectable interface and not through code they can wander around in. We build servers with the official Python SDK, `mcp` version 2, whose server class is called `MCPServer`.

The first server is `energyops.mcp_servers.energy`. It is read only by construction and says so to every client: both its tools are marked as read only, not destructive, idempotent and closed to the outside world. Its two tools are `list_sites`, which returns the demo site ids and the default site, and `get_fact_sheet`, which takes one site id and returns the numbered fact sheet for it, with each figure's exact display text, the notes about any missing data, and the same prompt text an agent would be given. Every number comes from our own Python functions, and a test compares the tool's answer to those functions figure by figure. The site argument is required on purpose. In an early version it was optional, and a call with a misspelled argument name quietly returned the default site's figures, which is the kind of wrong answer a model would never notice, so now it fails with a clear message instead. Nothing in the server takes a file path or a web address, and it reads only the built-in demo data.

The server talks over stdio, which means a client starts it as a subprocess and exchanges messages over its standard input and output. That is why nothing in the server may print to standard output. There is no network port and no sign-in to worry about, because the only thing that can talk to it is the program that started it.

To see it work, run `uv run python -m energyops.mcp_servers.check`. It launches the server as a subprocess exactly as an agent would, lists the tools, and prints the first fact for each site. It uses no model and needs no key. A fact sheet fetched over MCP can be turned back into the same `FactSheet` object that Python computes, using `FactSheetModel.to_fact_sheet`, so the figure check in the energy analyst works on it unchanged. The next step is to make the agent fetch its fact sheet through this server.
